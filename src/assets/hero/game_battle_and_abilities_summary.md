# Концепция боя и системы способностей

## 1. Общая концепция

Игра представляет собой PvP-матч в формате **3D match-3**.

Игрок управляет одним героем, собирает комбинации кубов на трёхмерном поле и в течение раунда накапливает:

- два типа урона;
- два типа защиты;
- энергию способностей.

Все боевые значения применяются не сразу, а рассчитываются **в конце раунда**.

Способности, которые физически изменяют поле, применяются сразу во время хода.

---

## 2. Структура PvP-матча

Матч состоит из **трёх раундов**.

```text
Начало матча
→ Раунд 1
→ Одновременный расчёт атаки
→ Раунд 2
→ Одновременный расчёт атаки
→ Раунд 3
→ Одновременный расчёт атаки
→ Определение победителя
```

### Основные правила

- У каждого героя есть `HP`.
- Текущее здоровье сохраняется между раундами.
- Боевые ресурсы раунда после расчёта очищаются.
- Энергия способностей сохраняется между раундами.
- Игроки наносят урон друг другу одновременно.
- Если здоровье героя становится равным `0`, он проигрывает.
- Если после третьего раунда оба героя живы, побеждает герой с большим процентом оставшегося здоровья.

---

## 3. Фазы раунда

### 3.1. Начало раунда

В начале каждого раунда герой автоматически получает:

```text
+20 энергии способностей
```

Энергия сохраняется между раундами.

При максимуме в `100` единиц без сбора тёмных кубов игрок получит:

| Раунд | Общая автоматическая энергия |
|---:|---:|
| 1 | 20 |
| 2 | 40 |
| 3 | 60 |

Тёмные кубы позволяют ускорить применение активной способности или накопить ультимативную способность.

### 3.2. Игра на поле

Игрок выполняет ограниченное количество ходов и собирает комбинации.

Во время этой фазы:

- кубы Огня и Льда накапливают урон;
- кубы Земли и Света накапливают защиту;
- кубы Тьмы накапливают энергию;
- способности поля применяются сразу;
- пассивные способности реагируют на игровые события.

### 3.3. Фиксация результата

После завершения ходов создаётся снимок состояния раунда:

```ts
interface RoundSnapshot {
  currentHp: number;
  maxHp: number;

  fireDamage: number;
  iceDamage: number;

  earthDefense: number;
  lightDefense: number;

  abilityEnergy: number;

  modifiers: CombatModifier[];
  queuedAbilities: QueuedAbility[];
}
```

После фиксации снимка ресурсы текущего раунда больше не изменяются.

### 3.4. Разрешение раунда

Порядок расчёта:

```text
1. Зафиксировать состояния обоих игроков.
2. Применить пассивные эффекты конца раунда.
3. Рассчитать эффекты активных способностей.
4. Рассчитать эффекты ультимативных способностей.
5. Применить бафы и дебафы.
6. Рассчитать огненный урон.
7. Рассчитать ледяной урон.
8. Применить земную и световую защиту.
9. Ограничить поглощение защиты.
10. Рассчитать лечение.
11. Одновременно изменить HP обоих героев.
12. Очистить временные ресурсы раунда.
13. Сохранить оставшуюся энергию.
```

## 4. Типы кубов и ресурсов

Принята схема из пяти типов кубов.

| Тип куба | Накапливаемый ресурс |
|---|---|
| Огонь | Огненный урон |
| Лёд | Ледяной урон |
| Земля | Защита от огненного урона |
| Свет | Защита от ледяного урона |
| Тьма | Энергия способностей |

### Связи ресурсов

```text
Огонь ↔ Земля
Лёд ↔ Свет
Тьма → способности
```

Огненный и ледяной урон считаются отдельно.

Земная защита поглощает только огненный урон.

Световая защита поглощает только ледяной урон.

---

## 5. Расчёт защиты

Защита не может полностью обнулить атаку.

Максимальное поглощение для каждого канала:

```text
80% входящего урона
```

Минимум `20%` урона всегда проходит в здоровье.

```ts
function calculateChannelDamage(
  incomingDamage: number,
  defense: number,
  maxAbsorbRatio = 0.8,
): number {
  const maxAbsorbedDamage =
    incomingDamage * maxAbsorbRatio;

  const absorbedDamage = Math.min(
    defense,
    maxAbsorbedDamage,
  );

  return incomingDamage - absorbedDamage;
}
```

### Пример

```text
Входящий огненный урон: 300
Земная защита: 500
```

Максимально можно поглотить:

```text
300 × 0,8 = 240
```

В здоровье пройдёт:

```text
300 − 240 = 60
```

Избыточная защита не переносится автоматически на следующий раунд.

## 6. Боевые ресурсы

```ts
interface RoundResources {
  fireDamage: number;
  iceDamage: number;

  earthDefense: number;
  lightDefense: number;

  abilityEnergy: number;
}
```

После завершения раунда:

| Ресурс | Сохраняется |
|---|---|
| Огненный урон | Нет |
| Ледяной урон | Нет |
| Земная защита | Нет |
| Световая защита | Нет |
| Энергия способностей | Да |
| Текущее HP | Да |
| Долгосрочные статусы | По правилам статуса |

---

## 7. Энергия способностей

Максимальная энергия:

```text
100
```

Предварительные стоимости:

| Способность | Стоимость |
|---|---:|
| Обычная активная | 40 |
| Усиленная активная | 60 |
| Ультимативная | 100 |

Тёмные комбинации дополнительно дают энергию.

Предварительные значения:

| Комбинация Тьмы | Энергия |
|---|---:|
| 3 куба | 10 |
| 4 куба | 18 |
| 5 кубов | 30 |
| Каждый дополнительный куб | +6 |

### Ограничения

- энергия сохраняется между раундами;
- ультимативная способность применяется не более одного раза за матч;
- кубы Тьмы, уничтоженные способностью, не дают энергию;
- каскады могут давать уменьшенное количество энергии;
- способность не должна сама полностью восстанавливать свою стоимость.

---

## 8. Способности героя

У каждого героя есть три способности.

### 8.1. Активная способность

- открывается первой;
- активируется игроком;
- расходует энергию;
- может изменять поле или создавать боевой эффект;
- обычно применяется один раз за раунд.

### 8.2. Пассивная способность

- работает автоматически;
- реагирует на игровые события;
- не требует ручной активации;
- не расходует энергию;
- может усиливать ресурсы, комбинации или действия героя.

### 8.3. Ультимативная способность

- открывается на высоком уровне героя;
- требует `100` энергии;
- применяется не более одного раза за матч;
- обладает сильным боевым эффектом;
- может комбинировать несколько стандартных эффектов.

```ts
type AbilityKind =
  | 'active'
  | 'passive'
  | 'ultimate';
```

## 9. Основные технические типы эффектов

Приняты следующие универсальные типы эффектов.

```ts
type AbilityEffectType =
  | 'modify-stat'
  | 'deal-damage'
  | 'heal'
  | 'destroy-cubes'
  | 'rotate-cubes'
  | 'transform-cubes';
```

### 9.1. Изменение характеристик

Один универсальный эффект покрывает:

- увеличение характеристик игрока;
- уменьшение характеристик врага;
- временные бафы;
- временные дебафы.

```ts
interface ModifyStatEffect {
  type: 'modify-stat';

  target: 'self' | 'enemy';

  stat:
    | 'attack'
    | 'outgoingDamage'
    | 'incomingDamage'
    | 'healingPower'
    | 'fireDamagePower'
    | 'iceDamagePower'
    | 'earthDefensePower'
    | 'lightDefensePower'
    | 'energyGain';

  operation:
    | 'flat-add'
    | 'flat-subtract'
    | 'percent-add'
    | 'percent-subtract'
    | 'multiply'
    | 'set';

  value: ValueExpression;
  duration: EffectDuration;
}
```

### 9.2. Нанесение урона

```ts
type DamageChannel =
  | 'fire'
  | 'ice'
  | 'true';

interface DealDamageEffect {
  type: 'deal-damage';

  target: 'enemy';
  channel: DamageChannel;

  value: ValueExpression;
  penetration?: number;

  timing: 'round-resolution';
}
```

- `fire` поглощается Землёй;
- `ice` поглощается Светом;
- `true` игнорирует обычную защиту и должен использоваться редко.

### 9.3. Восстановление здоровья

```ts
interface HealEffect {
  type: 'heal';

  target: 'self';
  value: ValueExpression;

  timing: 'round-resolution';
}
```

Лечение рассчитывается в конце раунда вместе с уроном.

### 9.4. Уничтожение кубов

```ts
interface DestroyCubesEffect {
  type: 'destroy-cubes';

  selector: CubeSelector;

  rewardPolicy: {
    grantDamage: boolean;
    grantDefense: boolean;
    grantEnergy: boolean;
  };

  triggerCascades: boolean;
  refillBoard: boolean;

  timing: 'immediate';
}
```

### 9.5. Поворот кубов

```ts
interface RotateCubesEffect {
  type: 'rotate-cubes';

  selector:
    | SelectedLineSelector
    | SelectedRegionSelector;

  axis: 'x' | 'y' | 'z' | 'selected';
  angle: 90 | -90 | 180;

  triggerMatches: boolean;

  timing: 'immediate';
}
```

### 9.6. Изменение типа кубов

```ts
interface TransformCubesEffect {
  type: 'transform-cubes';

  selector: CubeSelector;

  transform:
    | {
        type: 'fixed-element';
        element: ElementType;
      }
    | {
        type: 'hero-element';
      }
    | {
        type: 'random-element';
        excludeCurrent: boolean;
      };

  triggerMatches: boolean;

  timing: 'immediate';
}
```

## 10. Момент применения эффектов

Эффекты делятся на две категории.

```ts
type EffectTiming =
  | 'immediate'
  | 'round-resolution';
```

### `immediate`

Применяются сразу во время игры на поле:

- уничтожение кубов;
- поворот кубов;
- изменение типов кубов;
- перемещение кубов;
- создание специальных кубов;
- перемешивание поля.

### `round-resolution`

Рассчитываются в конце раунда:

- нанесение урона;
- лечение;
- увеличение характеристик;
- уменьшение характеристик врага;
- усиление защиты;
- пробивание защиты;
- преобразование ресурсов.

Одна способность может содержать эффекты обоих типов.

## 12. Формулы значений

Значения эффектов задаются через универсальные выражения.

```ts
type ValueExpression =
  | {
      type: 'constant';
      value: number;
    }
  | {
      type: 'stat';
      target: 'self' | 'enemy';
      stat: string;
      multiplier: number;
    }
  | {
      type: 'resource';
      target: 'self' | 'enemy';
      resource: keyof RoundResources;
      multiplier: number;
    }
  | {
      type: 'sum';
      values: ValueExpression[];
    }
  | {
      type: 'multiply';
      values: ValueExpression[];
    }
  | {
      type: 'min';
      values: ValueExpression[];
    }
  | {
      type: 'max';
      values: ValueExpression[];
    };
```

Это позволяет создавать способности, зависящие от:

- атаки героя;
- максимального здоровья;
- накопленного урона;
- накопленной защиты;
- текущей энергии;
- количества статусов;
- результата комбинации.

## 15. Управление контентом с бэкенда

Фронтенд содержит универсальный движок и обработчики эффектов.

Бэкенд управляет:

- героями;
- характеристиками;
- способностями;
- стоимостью энергии;
- множителями;
- длительностью эффектов;
- сезонными правилами;
- доступностью контента;
- анимационными пресетами;
- балансом.

С сервера приходит только декларативная конфигурация.

```text
Бэкенд
→ JSON-конфигурация способности
→ проверка схемы
→ выполнение зарегистрированных эффектов
```

Нельзя загружать и выполнять произвольный JavaScript с сервера.

### Ограничение

Через бэкенд можно создавать новые комбинации уже реализованных эффектов.

Если появляется принципиально новая механика, например:

- изменение направления гравитации;
- копирование способности противника;
- создание нового типа препятствий;
- управление полем противника;

потребуется новый обработчик и обновление клиента.

## 16. Разделение логики и визуализации

Игровая логика не должна зависеть от Three.js.

```text
Battle Engine определяет, что произошло.
Three.js показывает, как это произошло.
```

Пример события:

```ts
interface CubesDestroyedEvent {
  type: 'cubes-destroyed';

  cubeIds: string[];
  sourceAbilityId?: string;

  animationPreset: string;
}
```

Сначала движок изменяет состояние поля, затем анимационный контроллер показывает результат.

## 19. Зафиксированные основные решения

- PvP-матч состоит из трёх раундов.
- Урон применяется одновременно в конце раунда.
- Огонь и Лёд являются разными каналами урона.
- Земля защищает от Огня.
- Свет защищает от Льда.
- Тьма накапливает энергию способностей.
- Каждый раунд автоматически даёт `20` энергии.
- Максимум энергии — `100`.
- Защита может поглотить не более `80%` урона своего канала.
- Временные атака и защита сбрасываются после раунда.
- Энергия и HP сохраняются между раундами.
- У героя есть активная, пассивная и ультимативная способности.
- Способности собираются из универсальных типизированных эффектов.
- Способности поля применяются сразу.
- Боевые эффекты рассчитываются в конце раунда.
- Контент и баланс должны управляться с бэкенда через версионированные JSON-конфигурации.
